# Второй этап: статистика и ИИ-резюме тем

Вход — `topics.json`, полученный из `feedback_topics.py`. Выход — новый `topics_summary.json`, где темы представлены словарём по `topic_id`, статистика хранится в JSON-объектах, а ИИ добавляет короткие резюме на английском по умолчанию.

Программа не меняет число тем и их состав. Числа рассчитываются в Python, ИИ пишет только текст. В качестве начальной модели настроена `gpt-5.4`; её можно заменить параметром `--model` на доступную вашему аккаунту модель OpenAI с поддержкой Responses API и Structured Outputs.

## Быстрый запуск в вашей папке PowerShell

Новые файлы уже добавлены в `outputs\feedback_topics_package`. Переустанавливать зависимости не нужно: второй этап использует только стандартную библиотеку Python.

Пробный запуск: до трёх новых резюме, при этом статистика всех тем сохранится:

```powershell
& ".\.venv\Scripts\python.exe" ".\summarize_topics.py" ".\topics.json" --output ".\topics_summary.json" --limit 3
```

Если переменная среды `OPENAI_API_KEY` не задана, программа запросит ключ скрытым вводом. Введите или вставьте ключ в терминал. В файлы ключ не записывается. Не вставляйте ключ в чат или исходный код.

Для генерации потребуется действующий OpenAI API-ключ, доступ к выбранной модели и доступный баланс/лимит API. Фрагменты отзывов и агрегированная статистика будут переданы в OpenAI. Запросы платные; подписка приложения сама по себе не является API-ключом.

После проверки первых резюме обработать все оставшиеся темы:

```powershell
& ".\.venv\Scripts\python.exe" ".\summarize_topics.py" ".\topics.json" --output ".\topics_summary.json"
```

Без `.venv` можно заменить начало команды на `python`.

Полностью локальный запуск без ИИ и без ключа:

```powershell
& ".\.venv\Scripts\python.exe" ".\summarize_topics.py" ".\topics.json" --output ".\topics_stats.json" --stats-only
```

В этом режиме `summary` остаются `null`, а `status` равен `statistics_only`. Файл `topics_summary_stats_preview.json` уже создан именно в таком режиме на вашей таблице: он содержит все 460 тем и рассчитанную статистику, но не содержит ИИ-резюме.

## Что будет в итоговом JSON

Ниже сокращённый **условный пример структуры**, не статистика предоставленной таблицы:

```json
{
  "status": "complete",
  "overview": {
    "review_count": 100,
    "summary": "Покупатели в целом довольны автомобилем, но отмечают отдельные проблемы комфорта и управления."
  },
  "topics": {
    "T0001": {
      "title": "Комфорт сидений",
      "review_count": 100,
      "model": {"F70": 1.0},
      "country": {"GB": 0.7, "JP": 0.2, "ZA": 0.1},
      "engine_type": {"ICE": 1.0},
      "sentiment": {
        "positive": {"count": 70, "share": 0.7, "summary": "Хвалят удобную посадку и поддержку спины."},
        "negative": {"count": 10, "share": 0.1, "summary": "Жалуются на жёсткость сидений в длительных поездках."},
        "neutral": {"count": 20, "share": 0.2, "summary": "Описывают регулировки сидений без явной оценки."},
        "mixed": {"count": 0, "share": 0.0, "summary": "Смешанных оценок нет."},
        "undetermined": {"count": 0, "share": 0.0, "summary": "Неопределённых оценок нет."}
      },
      "summary": "Сиденья преимущественно оцениваются положительно, а жалобы касаются комфорта длительных поездок."
    }
  }
}
```

Числа от 0 до 1 являются долями. Например, `0.7` означает 70%. Сумма долей может незначительно отличаться от 1 из-за округления до шести знаков; целые `count` — точные.

В реальном JSON также сохраняются:

- `segments.country.JP` — статистика тональности **внутри Японии** по конкретной теме;
- `segments.model.F70` и `segments.engine_type.ICE` — аналогичные срезы;
- `country_engine_type.JP.ICE` — совместный срез страны и двигателя, рассчитанный по настоящим отзывам, а не перемножением долей;
- `signals` — обнаруженные кодом необычные доли негатива, точные числители, знаменатели и сравнение с остальной выборкой;
- `review_ids` — все ID отзывов, относящихся к теме;
- `evidence` — отправленные ИИ исходные примеры с ID отзывов, ID фрагментов, страной, моделью и двигателем;
- `sentiment.*.evidence_fragment_ids` — ссылки на примеры, подтверждающие текстовое резюме;
- `source_title` — первоначальное название математического кластера;
- `sampling` и `limitations` — описание отбора примеров и ограничения резюме;
- `review_metadata` на верхнем уровне — словарь метаданных каждого уникального отзыва.

Полные тексты всех отзывов остаются в исходном `topics.json`; новый файл не дублирует их целиком. `source.input_sha256` позволяет проверить, какой именно исходный JSON использован.

## Как различаются проценты

Для темы, содержащей 40 отзывов, допустим:

- из JP пришло 10 отзывов, из них 8 негативных;
- из GB пришло 30 отзывов, из них 12 негативных.

Тогда получаются три разных числа:

| Поле | Значение | Что означает |
|---|---:|---|
| `country.JP` | 0.25 | Из Японии пришла четверть отзывов темы |
| `segments.country.JP.negative_rate` | 0.80 | Среди отзывов темы из Японии 80% негативные |
| `segments.country.JP.share_of_all_topic_negative_reviews` | 0.40 | Япония даёт 40% всех негативных отзывов этой темы |

Дополнительно `topic_prevalence_in_source_segment` показывает, какая доля **всех исходных отзывов страны** относится к этой теме. Её знаменатель — вся страна в исходном наборе, а не только отзывы данной темы.

Единица анализа — отзыв. Без идентификаторов машин и репрезентативной выборки нельзя делать вывод «80% машин неисправны». Корректная формулировка: «8 из 10 отзывов этой темы из Японии негативные».

## Как находятся потенциальные проблемы

Код строит проверяемые сигналы до вызова ИИ. Метрика по умолчанию — доля `negative + mixed`, поскольку смешанный отзыв тоже содержит негатив. Доля строго отрицательных отзывов доступна отдельно в `negative_rate`.

Сигнал создаётся, когда:

- в группе не меньше `--min-segment` отзывов, по умолчанию 10;
- и доля негатива/смешанных оценок не меньше `--high-negative-rate`, по умолчанию 0.8;
- либо доля выше, чем в остальной выборке этой темы, хотя бы на `--min-gap`, по умолчанию 0.2, то есть 20 процентных пунктов; для этого сравнения в остальных группах тоже требуется минимум 10 отзывов.

Поля с единственным значением, например ICE во всех отзывах, не создают сигнал о проблемном подмножестве. Их полная статистика всё равно доступна.

Маленькие группы сохраняются в статистике; автоматический сигнал по ним не создаётся. Эти сигналы — описательные наблюдения, а не доказательство причины, статистической значимости или неисправности автомобилей. Поправка на множественные сравнения не применяется.

Точная фраза с процентами находится в `signals[].statement` и создаётся кодом. ИИ дописывает `signals[].interpretation` на основе приведённых отзывов. Модель не редактирует числовые поля; проценты и численные статистические утверждения в её собственном тексте запрещены и проверяются.

## Нейтральное, смешанное и неопределённое

Второй этап сохраняет тональность первого этапа. ИИ её заново не размечает.

- `neutral` — только явно нейтральная разметка;
- `undetermined` — тональность не удалось определить;
- `mixed` — присутствуют и положительные, и отрицательные признаки.

В текущем первом этапе нейтральные оценки явно не назначаются, поэтому их число в вашем файле равно нулю. Программа не превращает неопределённые отзывы в нейтральные ради удобных процентов. ИИ сообщит об отсутствии нейтральных отзывов, а для неопределённых опишет содержание примеров без придумывания оценки.

Глобальная тональность `overview.sentiment` рассчитывается отдельно: каждый исходный отзыв учитывается один раз по всем его фрагментам, включая фрагменты без темы. Суммировать числа по темам нельзя, поскольку один отзыв может относиться к нескольким темам.

## Объём запросов, восстановление и состояния

По умолчанию на тему отправляется максимум 16 примеров длиной до 1 000 символов. Отбор охватывает разные тональности, отмеченные страны и характерные фрагменты. Это не случайная выборка. Числа всегда рассчитываются по всем отзывам, а резюме содержания — по выбранным примерам.

Обычный полный запуск делает один запрос на каждую тему и один запрос для общей фразы после завершения всех тем. Для 460 тем это 461 запрос без повторных попыток. Ошибки сети, ограничение частоты, неполный ответ или нарушение схемы могут потребовать дополнительных запросов. Значение `--limit 3` ограничивает число новых резюме тем за один запуск, а не строгий денежный бюджет и не общее число HTTP-попыток.

Модель можно изменить:

```powershell
& ".\.venv\Scripts\python.exe" ".\summarize_topics.py" ".\topics.json" --output ".\topics_summary.json" --model gpt-5.4 --language en
```

После каждого резюме результат сохраняется. Рядом создаётся папка `topics_summary.cache` с ответами ИИ. Повторный запуск с теми же входными данными и настройками использует сохранённые ответы. Не удаляйте эту папку, если хотите продолжить без повторной оплаты готовых резюме. Изменение модели, языка, содержания запроса или настроек создаёт другой ключ кэша.

Статусы:

- `statistics_only`: есть все числовые данные, резюме отсутствуют;
- `partial`: часть резюме готова;
- `complete`: готовы резюме всех тем и общая фраза.

При ограниченном запуске все N тем остаются в результате; ещё не обработанные темы имеют `summary: null`. Общая ИИ-фраза создаётся после завершения всех тем, чтобы не выдавать вывод по небольшой части за вывод по всему набору.

В `ai.usage_this_run` записываются токены, HTTP-попытки и попадания в кэш текущего запуска. Это не денежная оценка: стоимость зависит от модели и актуального тарифа.

## Проверка

```powershell
& ".\.venv\Scripts\python.exe" ".\test_summarize_topics.py"
```

Тесты проверяют знаменатели долей, двойной счёт, совместные срезы, сохранение неопределённой тональности, восстановление из кэша, схему API-запроса и отклонение придуманных ссылок на отзывы. Сетевые ответы в тестах подменены контролируемыми примерами; это не проверка реального доступа к API и не оценка качества резюме модели.

На момент подготовки файлов выполнены локальные тесты и расчёт всех чисел вашего набора. Реальные запросы к OpenAI не выполнялись, поскольку API-ключ в доступном окружении не был настроен.

Интеграция использует [OpenAI Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). Поддержка формата у выбранной модели описана на [странице GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5.4).


## Быстрее: пять тем одновременно

По умолчанию используются GPT-5.4, английский язык и `--workers 5`.

```powershell
& ".\.venv\Scripts\python.exe" ".\summarize_topics.py" ".\topics.json" --output ".\topics_summary.json" --model gpt-5.4 --workers 5 --language en
```

Сначала остановите старый процесс через Ctrl+C. При остановке программа дожидается уже отправленных запросов и сохраняет их результаты; новые темы не запускает. Не запускайте два процесса с одним выходным файлом одновременно.

Пять запросов выполняются одновременно; ускорение ровно в пять раз не гарантируется. Скорость зависит от API, длины ответа и лимитов аккаунта. При ошибках 429 уменьшите `--workers` до 2 или 1. Параллелизм сам по себе не увеличивает количество тем или запросов, но другая модель имеет другую стоимость. GPT-5.4: $2.50 за миллион входных и $15 за миллион выходных токенов для стандартных коротких запросов согласно странице модели. Доступность зависит от вашего API-проекта.

Смена модели создаёт отдельный кеш: ответы GPT-5-mini сохраняются, но GPT-5.4 генерирует свои резюме заново с новой оплатой. Для ускорения с сохранением старой модели и её кеша используйте `--model gpt-5-mini --workers 5`. Параметр `--limit 3` по-прежнему ограничивает число новых тем даже при пяти обработчиках.

Официальная документация: https://developers.openai.com/api/docs/models/gpt-5.4 и https://developers.openai.com/api/docs/guides/latency-optimization .
Проверено локально: параллелизм, соблюдение лимита, разделение кеша моделей, сохранение при ошибках. Реальный API и ускорение на реальных данных не измерялись.
