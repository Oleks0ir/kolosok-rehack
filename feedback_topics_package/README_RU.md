# Темы отзывов из Excel в JSON

Программа работает локально. Она не вызывает AI API, не загружает модели и не использует нейросети. Темы создаются по TF-IDF и иерархической кластеризации с косинусным расстоянием и average linkage. Тональность определяется отдельными, явно записанными словарными правилами.

Имена и количество тем заранее не заданы. Алгоритм создаёт группы похожих формулировок; эти группы являются кандидатами в смысловые темы, а не гарантированно правильной классификацией. Название группы — характерные слова из данных, без генерации текста.

## Установка и запуск

Нужен Python 3.10 или новее. Распакуйте архив, откройте терминал в его папке и установите зависимости:

Проверенная среда: Python 3.12.14, NumPy 2.3.5, openpyxl 3.1.5.

```powershell
python -m pip install -r requirements.txt
```

При установке пакетов обычно требуется интернет. Сам анализ полностью автономный, без сети. Нужны только NumPy для математических операций и openpyxl для чтения Excel.

Запуск для исходной таблицы:

```powershell
python feedback_topics.py "C:\Users\Alex Sporik\Documents\F70_feedback_hackathon.xlsx" --output topics.json
```

Файл `sentiment_rules_en.json` должен находиться рядом с программой. Можно указать другой файл через `--rules`.

Запуск с явными настройками:

```powershell
python feedback_topics.py "input.xlsx" --output topics.json --sheet "Feedback_Explorer" --threshold 0.94 --group-by "Country" "Engine Type"
```

Для другой структуры таблицы:

```powershell
python feedback_topics.py "input.xlsx" --output topics.json --id-column "review_id" --text-column "review_text" --group-by "country" "engine_type"
```


## Входные данные

- Формат: `.xlsx`, заголовки в первой строке. По умолчанию читается первый лист.
- Обязательные столбцы: `ID` и `Customer Feedback`. Имена можно переопределить параметрами запуска.
- Правила нормализации и тональности рассчитаны на английский текст, как в предоставленном файле. Страна отзыва не определяет его язык. Для другого языка нужны соответствующие словари и правила; автоматического перевода нет.
- Повторяющиеся строки с одинаковым ID и текстом объединяются в один отзыв. Если одному ID соответствуют разные тексты, программа выдаст ошибку вместо потери данных.
- Исходный текст, номера строк Excel и все остальные столбцы сохраняются. Если метаданные одного ID различаются, сохраняется список всех значений.
- `Country`, `Engine Type`, `Feedback Type`, существующие VFC-метки и прочие параметры не участвуют в создании тем или вычислении тональности. Поэтому старые категории не навязываются новым.
- Пустые тексты сохраняются как отзывы без назначенной темы.
- Формулы Excel не исполняются. Для ячеек с формулами читаются сохранённые Excel значения, если они есть.

## Как создаются темы

1. Отзывы объединяются по ID.
2. Текст делится по предложениям, переносам строк, некоторым противопоставлениям и конструкциям с новым подлежащим. Очень длинные фрагменты делятся на блоки до 65 слов. Исходные фрагменты и их точные позиции сохраняются.
3. Удаляются общие слова; несколько форм слов объединяются вручную заданными правилами. Например, `seats → seat`, `comfortable / uncomfortable → comfort`. Это помогает объединить положительные и отрицательные высказывания об одном аспекте. Для тональности используется исходный фрагмент, поэтому отрицания не теряются.
4. Строятся униграммы и биграммы. Биграммы соединяют соседние оставшиеся нормализованные слова после удаления стоп-слов и не всегда являются дословной цитатой из отзыва.
5. Точные повторения фрагментов с точностью до регистра и пробелов объединяются для расчёта. Все связи с исходными отзывами остаются в результате.
6. Вычисляется TF-IDF:

   `TF = 1 + ln(число вхождений термина во фрагмент)`

   `IDF = 1 + ln((1 + число уникальных фрагментов) / (1 + число фрагментов с термином))`

   Векторы нормируются до длины 1. Фрагменты с пустыми векторами не кластеризуются и сохраняются как неназначенные.

7. Вычисляется косинусная близость. Расстояние равно `1 − близость`.
8. Иерархическая кластеризация объединяет группы по среднему расстоянию между всеми парами их фрагментов. Используется алгоритм цепочки ближайших соседей — nearest-neighbor chain.
9. Объединение ограничивается порогом `--threshold`. Названия групп составляются из характерных TF-IDF-терминов.

Алгоритм average linkage описан в [документации SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.cluster.hierarchy.linkage.html). В программе он реализован непосредственно с NumPy, поэтому scipy и scikit-learn устанавливать не требуется.

## Как управлять количеством тем

Главный параметр — `--threshold`. Это порог среднего косинусного расстояния, не вероятность и не оценка качества.

- Меньше порог — больше небольших, узких групп.
- Больше порог — меньше более широких групп; повышается риск смешения разных аспектов.
- Допустимый диапазон: от 0 включительно до 1 исключительно.
- Единственно правильного числа тем из этих данных математически не следует. Порог выбирается по нужной детализации и примерам в группах.

Проверенные варианты для предоставленного файла с текущими правилами обработки:

| Порог | Групп | Групп менее чем с 3 уникальными отзывами |
|---|---:|---:|
| 0.90 | 705 | 62 |
| 0.94, значение по умолчанию | 460 | 15 |
| 0.96 | 340 | 10 |

Это сравнение параметров, а не доказательство правильности 460 тем. Даже при 0.94 в одной группе могут оказаться комфорт, подогрев и другие свойства сидений. Проверяйте характерные слова и исходные примеры.

Маленькие группы никогда не удаляются: для них выставляется `small_topic: true`. Настройка `--small-topic-reviews` меняет только этот флаг.

По умолчанию `--min-df 2` оставляет термины, встречающиеся хотя бы в двух уникальных фрагментах. Для сохранения совсем редкой лексики используйте `--min-df 1`; число тем обычно увеличится. Неназначенные фрагменты всегда остаются в JSON.

## Тональность и подсчёты

Тональность не получается из кластеризации. Она определяется правилами из `sentiment_rules_en.json`:

- положительные и отрицательные слова/выражения;
- приоритет длинной фразы над входящими в неё отдельными словами;
- отрицание в окне до трёх предыдущих слов;
- отдельный признак пожелания, не равный автоматически негативу;
- список сработавших правил для проверки каждого результата.

Варианты `sentiment`:

| Значение | Значение для одной пары «отзыв — тема» |
|---|---|
| `positive` | Найдены только положительные признаки |
| `negative` | Найдены только отрицательные признаки |
| `mixed` | Есть и положительные, и отрицательные признаки |
| `undetermined` | Правила не нашли признаков оценки |
| `neutral` | Зарезервировано для явной нейтральной разметки; текущие правила его не назначают |

Если один фрагмент не определён, но другой фрагмент того же отзыва в той же теме положительный, итог пары будет положительным. Неопределённые части остаются видны в `fragments`.

Повторные упоминания одной темы в одном отзыве считаются как один отзыв. Внутри темы сумма пяти значений `sentiment_counts` равна `review_count`. Сумма `review_count` по всем темам может превышать число исходных отзывов.

`negative_share_of_topic` — число строго отрицательных отзывов / все отзывы темы, включая неопределённые. `reviews_with_any_negative` дополнительно включает смешанные. Пожелания `request_review_count` могут пересекаться с любой тональностью.

Сарказм, сравнения, дальние отрицания, местоименные отсылки и несколько аспектов в одной фразе могут давать ошибки. Значения rule scores и cosine similarity не являются вероятностями. Точность на независимой ручной разметке не измерялась.

## Структура JSON

Один JSON содержит и сводку, и все исходные данные с проверяемыми связями:

| Раздел | Содержимое |
|---|---|
| `source` | Имя и SHA-256 входного файла, лист, число строк и уникальных отзывов |
| `method` | Формулы, параметры, правила тональности и определения счётчиков |
| `summary` | Количество групп, фрагментов, назначенных/неназначенных отзывов |
| `warnings` | Ограничения метода и замечания к данным |
| `topics` | Все созданные темы |
| `reviews` | Все уникальные отзывы, полный текст, метаданные, строки Excel и ID фрагментов |
| `fragments` | Все фрагменты, исходные позиции, тема, тональность и сработавшие правила |

Каждый объект `topics` содержит:

- `topic_id`, `title`, `title_method`;
- `keywords`: характерные термины с весами;
- `review_count`, `review_share_of_all`;
- `fragment_count`, `unique_fragment_count`, `small_topic`;
- `sentiment_counts`, `negative_share_of_topic`, `reviews_with_any_negative`;
- `request_review_count`;
- `breakdowns`: количество уникальных отзывов и тональность по стране, двигателю и другим выбранным столбцам;
- `examples`: до пяти характерных фрагментов;
- `reviews`: список относящихся к теме ID отзывов, их тональность в этой теме, признак пожелания и ID подтверждающих фрагментов.

Полный текст отзыва получается через `topics[i].reviews[j].review_id → reviews`. Подтверждающие фразы — через `fragment_ids → fragments`. Исходный текст не дублируется в каждой теме.

У неназначенного фрагмента `topic_id: null`, а `unassigned_reason` объясняет причину. У полностью неназначенного отзыва нет пары ни с одной темой, но он сохраняется в `reviews`.

Пример чтения результата:

```python
import json

with open("topics.json", encoding="utf-8") as file:
    report = json.load(file)

reviews = {r["id"]: r for r in report["reviews"]}
for topic in report["topics"]:
    print(topic["topic_id"], topic["title"], topic["review_count"])
    print(topic["sentiment_counts"])
    for assignment in topic["reviews"]:
        original_text = reviews[assignment["review_id"]]["text"]
        # Здесь можно показать исходный отзыв в интерфейсе или выгрузить его.
```

## Результат включённого запуска

`F70_topics.json` создан из исходного файла при `--threshold 0.94`:

- 4 076 исходных строк, 2 128 уникальных отзывов;
- 7 596 фрагментов, 7 388 уникальных текстов фрагментов;
- 460 групп;
- 2 115 отзывов имеют хотя бы одну тему;
- 13 отзывов полностью без темы, но сохранены в результате;
- 525 фрагментов без темы, относящихся к 454 отзывам с неназначенным содержимым;
- 6 906 уникальных пар «отзыв — тема».

Эти числа характеризуют работу алгоритма, а не проверенную человеком полноту обнаружения жалоб.

## Проверки и ресурсы

Запуск тестов:

```powershell
python test_feedback_topics.py
```

Проверяются формула TF-IDF, косинусные расстояния, совпадение кластеризации с независимым полным перебором на 420 комбинациях данных и порогов, отрицания, пожелания, повторяющиеся ID, пустые тексты, точные ссылки на исходные фрагменты и отсутствие двойного счёта.

Память для матрицы близости растёт как квадрат числа уникальных фрагментов. На исходном файле матрица для 6 968 непустых векторов занимает примерно 370 MiB; программе нужна дополнительная память для текстов, словарей и JSON. Значение `--max-memory-mb 768` ограничивает оценку памяти этапа вычисления близости, а не весь процесс. При превышении программа завершается с понятной ошибкой, не отбрасывая отзывы молча.

Одинаковые данные, порядок строк, параметры, правила и среда выполнения дают одинаковую разметку. Поле времени выполнения может меняться. При изменении корпуса номера и границы тем могут измениться; это не постоянный справочник тем.
